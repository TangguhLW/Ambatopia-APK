# Windows 0.32 — wearable speed, hover, rainbow and foreground pets

This revision only changes the native Godot project. Windows debugging is used; old Ambatopia web files, APKs, accounts and cloud configuration are outside the change. Existing game windows are not closed.

## Causes and fixes

Pets were drawn before `draw_native_body()`, so the player's body hid them at overlaps. Both recovered animated pets and the existing fallback pet path now draw after the equipment/body passes. The original following positions, delayed motion history and animation tracks are retained. This changes visual layering, not collision or pet pathfinding. The normal pet drawing path compensates for the owner's visual lift so a ground pet does not bob up and down with hovering clothing.

Movement effects previously depended on description phrases such as “move faster.” This missed Neon Nerves (5264), Speed Medallion (4988) and StarBoard (1740). `capture-wearable-032.mjs` captures nine populated [Speedy tables](https://growtopiawiki.com/w/Mods/Speedy), matches exact normalized item names to the inspected simulator catalog, retains page hashes and writes 309 confirmed item IDs. The Hair table returns 404 and is explicitly recorded, not treated as an empty successful source. The runtime applies these worn buffs and exposes their labels in the player profile. Unequip removes their influence through the appearance cache; no permanent/timed consumable modifier is injected. Land-only Speedy stops affecting water, and existing Frozen/Xenonite restrictions remain enforced.

The existing creative speed multiplier, 1.25, is retained. This revision establishes item identity and functional speed, not native movement constants, exact stacking magnitudes or all current official-server buff semantics. In particular, Neon/Medallion stacking with other speed groups remains unverified and is not claimed complete. Remaining description-based abilities outside the new Speedy registry also require separate audits.

Spirit Guide (6064) has the captured `hb` and `nw` flags. The source applies `-5 + 2*sin(2*pi*t)` as visual body lift and suppresses walking feet. The reconstruction now applies that whole-body lift, including equipment, separately from the physical collision body. StarBoard uses its distinct recovered `ro.ride.lift` expression, `-9 + 2*sin(2*pi*t)`, and its original arm-angle expressions. A simple ground shadow stays at physical feet while the body floats. The shadow's geometry/opacity are an adaptation; an exact native shadow sprite was not identified. This does not implement unlimited flight or the Spirit Board break-chance perk.

Neon Nerves declares typed emitter 39; it had been cataloged but was not dispatched by either the legacy particle interpreter or ancestral handler. The existing typed-memory renderer now executes this specific flat definition with its original memory parameters, half-second life, actual `particles` atlas cell (13,13), and movement gate. Source byte 436 selects the six-segment rainbow cycle with the captured 10-second sine clock. Source byte 529 selects the **behind-body** particle pass, preventing an opaque trail from covering the player. Both normal/additive behind passes are supported, while pets remain in front of the body. Emission stays bounded by the existing 48-particle typed pool. Stationary and unequipped trails expire normally.

Speed Medallion continues using its own captured lightning program 236; StarBoard keeps its captured star program 80. Those are not replaced by the Neon emitter or a common generic sparkle. Hover-aware origins keep these world-space particles from bobbing with the player after emission.

## Source and scope

`research/wearable-032/sources.json` contains URLs, page hashes, matching results and the decoded simulator source hash. `source-snippets.txt` retains the source hover equation, typed rainbow rule and flags. `live-source-check.json` records a fresh fetch of the current simulator bundle. The original local `particles.rttex` and the existing converted effect pack remain the texture authority; no AI image or web thumbnail replacement was added.

The targeted records are 1740, 4988, 5264 and 6064. The registry broadens working Speedy identities, but catalog presence does not prove every item's special animation or buff is complete. The audit records **320 other item records with typed emitter rows requiring further per-emitter verification**. Some can also have existing native XML or other rendering paths; that number must not be interpreted as 320 items entirely lacking effects. Detailed Spirit Board probabilities, all special buff stacks, and all other item-specific programs remain outstanding. The five unrecovered Starship layouts from 0.31 are unchanged.

## Verification

Focused red tests reproduced the three missing speed buffs, absent hover model and absent Neon emitter. Another red test reproduced land Speedy affecting swimming. The focused suite then passes 636 checks, including all 309 mapped clothing buffs, source hover phases, real atlas coordinates, rainbow color change, source back-layer flag, original lightning program, expiry, unequip and Xenonite restrictions.

The Windows QA harness exercises the four individual wearables while walking, captures their rendered appearance, captures a pet overlapping the player and measures a combined Neon/Spirit Guide/StarBoard scenario. A profile isolated from real accounts is used. Final exported results, build hashes and unchanged-file verification are retained in `evidence/wearable-032-summary.json`; only those final results establish completion of the tested paths. No Android or live crowded-multiplayer performance claim is made.

Final build: **`build/windows/Ambatopia-0.32.1.exe`**. Final native regression: **316,282 checks, zero failures**. Focused wearable suite: **636 checks, zero failures**. Exported Windows UI: **376 checks, zero failures**. All **123** provenance entries match, along with **13** recorded old-web source references, **two** prior APKs, the original executable and three original particle textures. The interrupted 0.32.0 GUI run did not produce a final report and is not used as passing evidence. The final 0.32.1 report includes the duplicate-pet fallback guard.

The combined 180-frame effect sample recorded **56.13 FPS mean**, **17.634 ms p95**; it does not establish a locked 60 FPS. Final Neon, Spirit Guide, StarBoard, lightning and overlapping-pet captures were inspected. Further pose audit identified seven other ride expressions depending on runtime variables beyond the current time-only lift input (Scavenger Wheels 7296/7298, 7384, 7918, 8952, Super Speeder 12636 and Slopestyle Bike 13162). Those context-sensitive lifts remain unverified; the two targeted hover equations here only require the time input. This is another explicit limitation on a whole-catalog 1:1 claim.
